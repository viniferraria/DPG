# Purpose

Bénard and Josse, "Variable importance for causal forests: breaking down the heterogeneity of
treatment effects" (<http://arxiv.org/abs/2308.03369v1>, section 4.2), validate a variable-importance
measure on the ACIC 2019 Data Challenge. They write: "We run a second batch of experiments using the
data from the ACIC data challenge 2019 ... where the goal was to estimate ATEs in various settings. The
input data is taken from real datasets available online on the UCI repository. Next, outcomes are
simulated with different scenarios, and the associated code scripts were released after the challenge.
Since the data generating mechanism is available, we have access to the variables involved in the
heterogeneous treatment effect." This suite reuses that protocol with DPG: fit a `CausalForest`, build
its DPG, rank predicate nodes by centrality, and score the top-k features against the known effect
modifiers. Scoring follows the reference protocol of [causal synthetic scenarios](/experiments/causal-synthetic-scenarios.md)
(see Scoring below). Structure mirrors [MONK's problems](/experiments/monks.md).

# Data and ground truth

- Source: the official ACIC 2019 page, <https://sites.google.com/view/acic2019datachallenge/data-challenge>
  (low-dimensional track, 3200 files, 100 per DGP, 32 DGPs; no registration). Each CSV is
  `Y, A, V1, ..., Vp`: continuous or binary outcome, binary treatment, pre-treatment covariates.
- The page publishes the true population ATE per file (`lowDim_trueATE.csv`: `filename, DGPid,
  trueATE`) and the R generator scripts (`ACIC_2019_Generate_DGPs.zip`). **It does not publish
  feature-level labels or CATE.** The effect modifiers are read from the R code.
- Experiment: **DGP 64** = `low_studentperf2_cont_sim.R`, modification 4 (UCI `student-por`, n = 649,
  29 covariates, continuous Y, true ATE 3.625). The generator draws
  `Y ~ N(2*A + 0.5*A*rank(age)/100 + lp(X), sd)`, so the CATE is `2 + 0.5*rank(age)/100` and age is
  the only effect modifier. After the generator drops `address` (the treatment) and `G1..G3`, age is
  the third covariate, `V3` (matches the paper's `X(3)`).
- **DGP 39** = `generate_simSpam_cont.R`, "Mod 3" (UCI spambase, 500 x 24 files, 22 covariates, continuous Y,
  true ATE 6.27). Line 159 of that script: `Y.mod3 <- -3 +  3* A.mod3 * (1 - d[,21]  + 2.2* d[,10]  ) + drs.mod3 + rnorm(n)`.
  `d` is `(Y, A, V1..V22)` (line 42, `colnames(d) <- c("Y", "A", paste0("V", 1:(ncol(d)-2)))`), so `d[,21]` = `V19`
  and `d[,10]` = `V8`: CATE = `3 * (1 - V19 + 2.2 * V8)`, the paper's `X(8)` and `X(19)`. Checked on the data:
  regressing Y on A, the standardised V's and A x V over 20 merged DGP-39 files, the largest interaction
  z-scores were V8 (242.6) and V19 (46.1), then V1 at 1.8.
- `SCENARIO_GROUND_TRUTH = [(64, ["V3"], 1), (39, ["V8", "V19"], 20)]` (DGP id, true features, files merged per
  dataset). Confounders (sex, absences, nursery, failures, freetime,
  goout, parental education and job, famsize, Pstatus) are deliberately **not** ground truth.

# How to run

```bash
uv run python experiments/acic2019/fetch_acic2019.py          # ~200 MB download, keeps 100 files per DGP
uv run --extra causal python experiments/acic2019/run_acic2019.py --n-datasets 5
```

Constants: `RANDOM_STATE = 42`; `TOP_K = 3` and `METRICS` come from the shared
[experiments.causal_accuracy](/modules/experiments-causal-accuracy.md) module, as in the reference. The model is
`CausalForest(n_estimators=100, criterion="het", random_state=42, n_jobs=-1)` fitted on `X=V, T=A,
y=Y`. `dpg_config` is passed explicitly (`perc_var=0.0001`, `decimal_threshold=3`,
`aggregated_transitions`, `context_order=1`, igraph) so the run does not depend on the CWD's
`config.yaml`; see [config resolution](/conventions/config-resolution.md). For DGP 39 the 20 first files (numeric order) are concatenated
into one n = 10,000 dataset; `--n-datasets` counts such groups (up to 5 with the 100 files fetched).

# Scoring

The reference scoring, imported from the shared module and called as
`causal_accuracy_rows(explanation.node_metrics, gt_features, run_key, split_idx)`: predicate nodes are ranked by
each metric, the top `TOP_K = 3` node labels are mapped to their feature name (the token before the first
space), and precision and recall are computed on that set. The reference has a single `TOP_K`, so the earlier
`TOP_KS = (1, 3)` was reduced to `TOP_K = 3`.

**No deviation any more.** The `Pred` exclusion that was ACIC's named deviation (a causal forest is a
regression DPG whose leaves are `Pred ` nodes) is now applied by the shared `extract_top_k_features` in every
suite, so ACIC passes no keywords. `intersection` is written sorted.

An earlier version of this runner summed node scores per feature and wrote rank columns. Both were removed;
they are recorded as untested ideas in [per-feature score aggregation](/opportunities/per-feature-score-aggregation.md)
and [true-feature rank column](/opportunities/true-feature-rank-column.md).

# Outputs

Same names as monks, one timestamp per run: `results/node_metrics_<ts>.csv` (the reference schema, with
`split` the first file's numeric id; old files use `node_index`, `in_degree_nodes`, `out_degree_nodes`,
`split_idx`, see [node_metrics schema change](/side-effects/node-metrics-schema-unification.md)),
`results/causal_accuracy_<ts>.csv` (`experiment, split, k, ground_truth, explanation_top_features,
metric, intersection, precision, recall`, as in the reference; `k` is always 3), both appended per dataset with
LF line endings ([why](/side-effects/csv-line-endings-lf.md)), and `states/dgp<id>_CausalForest_split<id>_{dpg_explainer,explanation}_<ts>.pkl` (about 3 MB per
DGP-64 dataset, 10 MB per DGP-39 dataset). The log line `CATE RMSE on low<id>.csv` compares the forest to the true CATE above.

Observed smoke runs, one dataset each (anecdotes, not results). **Superseded (summed scoring):** these were
produced when the runner summed node scores per feature and used `k` in {1, 3}; they have not been re-run with
the reference scoring and are not current results.

- DGP 64, `low9.csv`: CATE RMSE 0.5763, 959 node records. Top-1 was `V3` for Betweenness and Percolation
  centrality and `V29` for the other four; top-3 contained `V3` for every metric (precision 1/3, recall 1.0).
- DGP 39, files `low2007.csv..low2198.csv` (n = 10,000): CATE RMSE 2.6566 (true CATE sd 5.71), 1851 node
  records, about 6.5 minutes. Top-1 was `V22` for all six metrics (precision and recall 0). Top-3 hit a true
  feature only for Collective influence (`V22;V8;V15`, precision 0.33, recall 0.5). The forest itself is not
  the cause: its `feature_importances_` on the same data put `V8` first at 0.939 (`V12` 0.022, `V22` 0.020),
  and `V19` is absent from the top five. The summed ranking is analysed in
  [per-feature score aggregation](/opportunities/per-feature-score-aggregation.md).

# Limitations, side effects and errors

## Estimand mismatch: ATE challenge, feature-ranking question

The challenge estimand is the population ATE. DPG ranks features by graph structure of the forest's
splits, which is neither an ATE nor an importance of effect heterogeneity. Centrality rewards nodes
that many trace paths pass through, so a feature the forest splits on for variance reasons ranks high
even if it does not modify the effect. Example from the smoke run (superseded, summed scoring): `V29` (absences, a prognostic and
propensity variable, not an effect modifier) beat `V3` on Local reaching, Closeness, Harmonic and
Collective influence at k = 1. Scoring `V29` as a miss is correct against this ground truth, but it is
a property of DPG, not necessarily a forest failure.

## Ground truth is effect-modifier only, derived from code

Only the effect modifiers are true (`V3` for DGP 64; `V8`, `V19` for DGP 39). A top-3 containing `V29` and `V27`
is scored precision 1/3 even when those are real confounders. With one true feature, precision at k = 3 is capped at 1/3 and
recall is binary (a rank column is an [open idea](/opportunities/true-feature-rank-column.md)). The ground truth is read from the released R scripts by hand, not from a
published label file; a wrong index mapping would silently change it. Example: `V3` is age only
because `address` and `G1..G3` are dropped (`low_studentperf2_cont_sim.R` lines 15-17); DGP 39's `V8`/`V19` rely on the
`d[,k]` to `V(k-2)` offset. An off-by-two slip would silently score the wrong features.

## CausalForest criterion must be `het`

econml's default `criterion="mse"` splits on prognostic signal and misranks prognostic versus
effect-modifier features (see [causal forest support](/concepts/causal-forest-support.md)). The runner
fixes `criterion="het"`. Example: replacing it with `"mse"` in `MODEL_FACTORIES` runs without error
but no longer measures effect heterogeneity.

## `extract_communities` raises on a regression DPG

A causal forest has `Pred` leaves and no `Class` sinks, so `explain_global(communities=True)` raises
`ValueError: extract_communities requires a classifier DPG with at least one 'Class ' sink node;
regression DPGs ('Pred ' leaves) are not supported by this community extraction in 0.3.0.` run_monk.py
passes `communities=True`; this runner passes `False`. Observed when the monks default was tried: the
per-run `except` logged `Failed: dgp64_CausalForest` and wrote nothing.

## Per-run exceptions are swallowed

The explanation step is wrapped in `except Exception` (as in monks): a failure is logged with
`logger.error` and a traceback, the batch continues, and that dataset gets no CSV rows. Example: a
missing metric column would log `Failed: dgp64_CausalForest: 'Percolation centrality'` and the run
would still print `All experiments completed.`

## Data is not checked in; fetch needs network and about 200 MB

The site states no redistribution licence for the CSVs (its only stated terms cover submissions), and
the covariates come from UCI datasets, so `datasets/` is gitignored and `fetch_acic2019.py` downloads
the official files. It downloads the whole 200 MB zip to a temp file and keeps the requested DGP's 100
files. Failure modes: no network gives a `urllib.error.URLError`; a missing dataset gives
`FileNotFoundError: No datasets in .../datasets/dgp64; run fetch_acic2019.py first.`; an unknown DGP
gives `DGP ids not in the low-dimensional track: [999]`. The Dropbox and Drive links are hard-coded
and may rot.

## Runtime and `--n-datasets`

Each DGP-64 dataset takes about 1.5 minutes (tracing 649 samples through 100 trees = 64,900 paths). Each
DGP-39 dataset (n = 10,000, 1,000,000 paths) took about 6.5 minutes in the smoke run. The default of 5
datasets per DGP is therefore roughly 40 minutes; `--n-datasets 100` is not possible for DGP 39 (100 files make 5
groups of 20) and is about 2.5 hours for DGP 64. Averages over 5 datasets are noisy.

## Fit on all rows, no held-out set

Unlike monks (train/test split) the forest and the DPG use the same rows, because the target is the
explanation. The only model-quality check is the logged CATE RMSE against the known true CATE
(`true_cate_dgp64`, which is DGP-64 specific: it hard-codes `V3` and the `rank/100` form). Adding a
DGP needs its own true-CATE function or the RMSE call fails.

## Differences from the paper

The paper compares an importance measure `I_n^(j)` and grf's variable importance, not DPG.

**31 versus 29 inputs.** The paper says student performance 2 has "31 input variables", while DGP 64 has 29
covariates. Evidence from the generators and data: `low_studentperf2_cont_sim.R` takes `A<-dat[,4]` (address),
`Y<-apply(dat[,31:33],1,mean)` and `dat<-cbind(Y,A,dat[,-c(4,31:33)])` (lines 15-17), leaving 29 covariates; its
files have 31 *columns* (`Y`, `A`, `V1..V29`), which matches "31" if columns were counted. The only 31-covariate
student-performance files are DGPs 57-60 (`low_studentperf_cont_sim.R`, `A<-dat[,23]` romantic, `Y<-dat[,3]` age, lines 18-20),
but there the heterogeneity is `risk.edu<-log((rowSums(dat[,5:22])+dat$higher*3+dat$health*5)+10)` (line 90), which spans
`V3..V20` plus `higher` and `health`, not `V3` alone, and `V3` is the binary `address` (checked: values 0/1 in DGP 60,
14-21 in DGP 64). The paper's "involved in the heterogeneity: X(3) only" therefore matches DGP 64 and `V3` = age. The
"31" is most plausibly a column count; that last step is an inference, the paper does not say. The runner is unchanged.
(The script's comment `simName = "studentperf2_mod4"` sits in the *other* file, which is a naming ambiguity in the generator.)

**Spam email and "Scenario 4".** The paper reports `X(8)` and `X(19)` for "Scenario 4", but in
`generate_simSpam_cont.R` those are the modifiers of "Modification 3" (DGP 39, ATE 6.27). "Modification 4" (DGP 40,
ATE 6.962) has `5 + 2*log(W4.2 * W4.1)` with `W4.1 = (2*d[,13]+5 + d[,22]) / (d[14]+2)` and `W4.2 = cut(d[,17], 8)`
(lines 178-179, 189), i.e. `V11`, `V20`, `V12`, `V15` (data check: top interactions V15, V12, V11). The paper's scenario
numbering therefore does not equal the script's modification numbering for spam, while it does for student
performance 2 (mod 4 in both). The suite follows the paper's *variables* (DGP 39), not its scenario number.
The binary spam script (`generate_simSpam_binary.R`) is not used. Whether the paper merged continuous-outcome files is not stated; this suite assumes it did.

## Merged spam files are bootstrap draws

Each DGP-39 file is a 500-row sample *with replacement* from the `n = nrow(d)` spambase rows (`sample(1:n, n.b, replace = TRUE)`,
line 168 in the Mod 3 loop), with A and Y regenerated per file. Concatenating 20 files
gives n = 10,000 rows drawn from that finite population, so covariate rows repeat across and within files. The forest and the
DPG are fitted on these duplicates (no held-out set), and the same `V` rows appear with different outcomes. The paper
does the same merge; this does not recreate its exact files (the 100 files are fixed, a different pick would differ).

## Side effects

Importing `run_acic2019` creates `dpg_explainer_<timestamp>.log` in the CWD (same as monks), and each
dataset writes two pickles to `states/`. Nothing is cleaned between runs.

# Test coverage

`tests/test_run_acic2019.py` loads the runner by path after `chdir` to a temp dir. It checks
`true_cate_dgp64` and `true_cate_dgp39`, the `SCENARIO_GROUND_TRUTH` features, dataset
grouping/merging/loading including `FileNotFoundError`, and a tiny `CausalForest` end to end through
`_build_explanation` (guards the `communities=False` choice), then runs the shared `causal_accuracy_rows` on
the resulting node metrics and checks it returns one row per `METRICS` entry with non-empty top features (so `Pred` leaves do not empty the ranking). Scoring and CSV schema are
covered in `tests/test_causal_accuracy.py`. It does not download data.
